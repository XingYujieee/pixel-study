# 像素书房本地测试与修复报告

日期：2026-10-06 至 2026-10-07。输入为用户提供的桌面 `pixel-study` 源码，原目录未修改。用户确认没有远程 Git 仓库，交付本地分支、补丁和完整源码，不创建线上 PR。

## 结论

自动化测试与构建通过，但**不能据此宣布所有功能已完成原生验收**。共通过 108 项前端测试、51 项 Rust 测试、22 项浏览器检查。部分界面检查只验证挂载，不能代表完整功能链路通过。

测试环境：本机 Apple Silicon/macOS、Node 24.4.1、Rust stable、项目锁文件中的依赖。浏览器使用独立 Chromium 会话及项目自带的 Tauri 模拟后端；Rust 测试使用真实临时目录及本机 HTTP 模拟服务，没有使用用户的笔记库或 AI 密钥。

独立标识 `app.pixelstudy.review` 的 macOS 测试应用成功构建并启动。原生 UI 自动化因 ScreenCaptureKit 报错 `-3811`（无法开始音视频捕获）而受阻。因此没有把原生读写、输入法候选窗或 Finder 拖放列为已通过。

## 修复内容

| 优先级 | 问题与触发条件 | 修复与验证 |
| --- | --- | --- |
| P1 | Markdown 与 Word 切换时两个编辑器同时留在容器中，Word 正文被挤出书页 | 挂载当前编辑器时替换容器子节点，保留另一编辑器会话；新增双向容器替换测试，并复核浏览器截图 |
| P1 | 切换库时先执行后端 `vaultOpen`，再保存旧会话；同名相对路径继续复用旧库正文 | 先保存正文、布局和待写附加数据；有冲突或保存错误时阻止切换；清空两个编辑控制器，切换后重新加载前端。增加操作顺序、阻止切换和同名文档重新读取测试 |
| P1 | Markdown 冲突文档关闭再打开，显示最初正文，本地修改消失 | 关闭前缓存最新 EditorState 和滚动快照；新增测试确认正文和撤销记录保留，修复前失败 |
| P1 | Word 外部刷新期间继续输入，读取完成后覆盖刚输入的内容 | DOCX 读取转换结束后再次检查本地修改，发生竞争时进入冲突并写草稿；延迟读取测试修复前失败 |
| P1 | Word 原文件删除后恢复草稿直接返回，无法看到草稿；删除/冲突没有立即落恢复草稿 | 删除时立即保存本地草稿；缺失文件恢复为 missing 会话，用户明确重建才写回；增加删除、恢复与重建测试，修复前失败 |
| P1 | 保存失败或冲突未解决时关闭窗口仍继续退出 | 保存后检查两个控制器，有未保存内容则取消关闭并提示；同时清理 StrictMode 中迟到的关闭监听注册。此项经过源码检查，原生窗口关闭链路尚待人工验收 |
| P2 | 向 CRLF 笔记追加多段文字（例如插入 AI 回答），抛出光标越界异常 | 使用 CodeMirror 的 Text 长度计算光标，写回仍保留 CRLF；新增回归测试修复前失败 |
| P2 | 已删除的空 TXT/Markdown 点“重新创建”后文件仍不存在 | 显式创建不再被“正文没有变化”判断跳过；新增空文件重建测试修复前失败 |
| P2 | Word 在外部被换成复杂格式后仍保持可编辑，跳过格式损失确认 | 每次外部刷新重新检测只读状态并同步 contentEditable；新增测试修复前失败 |
| P2 | 根目录书架显示保存到库根目录，实际新建到 Notes/ | 前端保留空目录参数；Rust 区分 None（默认 Notes）和空串（库根目录）。Rust 回归修复前失败，浏览器跨层参数检查通过 |

为切换库而重新加载前端，会关闭旧库的临时面板和未持久化聊天界面。这是避免旧库的附件、撤销操作及缓存串入新库的保守实现；正文必须先成功保存。所有补丁不改动用户现有文件。

## 重跑

在解压的源码根目录运行（需要项目 README 中的依赖）：

```bash
pnpm install --frozen-lockfile
pnpm test
pnpm typecheck
pnpm build
cargo test --manifest-path src-tauri/Cargo.toml --workspace -- --nocapture
cargo clippy --manifest-path src-tauri/Cargo.toml --workspace --all-targets -- -D warnings
```

浏览器回归需要另行安装 `@playwright/cli` 及其浏览器。两个终端分别运行：

```bash
pnpm exec vite --host 127.0.0.1 --port 1427
```

```bash
playwright-cli -s=pixel-review open about:blank --headed
playwright-cli -s=pixel-review run-code --filename=scripts/e2e/review-setup.js
playwright-cli -s=pixel-review run-code --filename=scripts/e2e/review-smoke.js
playwright-cli -s=pixel-review eval 'window.__REVIEW_RESULTS__'
playwright-cli -s=pixel-review close
```

执行浏览器脚本期间不要修改源码，以免 Vite 热更新让测试动态导入与界面持有不同模块实例。发生此情况应重启 Vite 并重新执行。脚本使用虚构笔记和模拟 IO，不访问真实笔记。

## 交付与应用

- `pixel-study-fixed.zip`：包含全部修复源码，不含依赖、构建缓存及用户笔记。
- `fixes.patch`：相对用户提供源码的审阅/应用补丁。
- `pixel-study-review.bundle`：本地 Git 历史，含基线 main 和 `review/data-safety-and-regression` 分支，可保留审阅记录。
- `像素书房测试.app.zip`：独立标识的调试构建，供后续人工验收；用户原来的应用不受影响。
- `evidence/`：测试日志、修复前失败记录和截图。

建议先使用完整源码包另建副本。若要将补丁应用到原项目，先备份并在原项目目录运行 `git apply --check /路径/fixes.patch`，通过后再 `git apply /路径/fixes.patch`。不需要原目录已有 `.git`。应用后重新构建，旧的 `.app` 不会自动更新。

恢复本地审阅分支：

```bash
git clone pixel-study-review.bundle pixel-study-reviewed
cd pixel-study-reviewed
git switch review/data-safety-and-regression
```

本次不改变原有手动验收清单的勾选状态。上表未验证项仍是发布前待办。
