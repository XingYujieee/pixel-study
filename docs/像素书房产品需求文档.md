# 像素书房产品需求文档

文档版本：PRD 1.0　｜　日期：2026年10月7日　｜　适用产品版本：0.1.0 原型至首个稳定版

面向产品负责人、开发和测试。本文规定像素书房的产品定位、功能行为、数据规则、交互要求、验收标准和发布顺序，作为后续开发与验收的统一依据。产品以可靠的本地笔记为核心，以第一人称像素书房提供空间整理和沉浸写作体验。

当前结论：核心编辑及部分原生文件流程已经验证；完整原生验收尚未结束。首个稳定版必须先合入修复、完成数据安全与输入法验收，再扩大环境和游戏化功能的发布范围。本文新增的性能指标、分阶段范围和待决策项属于建议产品基线，不表示已经实现或已由负责人确认。

## 1 产品定位与设计原则

### 1.1 一句话定位

像素书房是一款优先适配 macOS 的本地个人笔记与资料整理软件。用户在原创方块风格书房中用书架组织文件、在书桌写作、用鱼塘收集灵感，也可以直接搜索和进入完整编辑界面。Markdown、TXT 和附件仍是普通本地文件，可与 Obsidian 共用同一目录。

### 1.2 要解决的问题

- 笔记和附件集中在目录中，缺少易记的空间位置与主题分区，回找材料需要反复搜索。
- 随手记录与正式写作之间缺少自然的整理过程，零散想法容易长期堆积。
- 用户希望拥有安静、有个人风格的写作环境，同时保留成熟编辑器的输入效率。
- 已经使用 Obsidian、Finder 和 Word 的用户不希望再迁移到封闭数据库，也不希望两份内容互相同步出错。

以上是本产品的设计假设，并非已经完成用户访谈或市场验证的结论。首轮试用需要验证空间记忆是否实际帮助回找、氛围是否帮助写作，以及整理动作是否增加负担。

### 1.3 产品原则

1. **正文可独立使用。** 应用卸载后，笔记和附件仍能由其他应用打开；布局和索引不能成为正文的唯一存储。
2. **文件正确性优先。** 保存、冲突、恢复和链接保真优先于动画、主题与装饰。
3. **空间操作与文件操作分清。** 挪动家具或收藏引用不移动文件；实际移动、回收、覆盖必须让用户看见来源、去处和恢复方式。
4. **游戏体验可以绕过。** 搜索、新建和专注编辑始终可直达，不能要求走路、等待动画或完成任务后才能写作。
5. **反馈温和可关闭。** 不设置连续打卡、惩罚、排名、资源消耗或限时奖励。天气、灰尘、发光和冒泡只作提示。
6. **核心离线可用。** AI 与真实天气是主动启用的扩展，网络异常不能阻止本地笔记操作。

### 1.4 独到的设计选择

空间与文件采用两套独立结构：一个文件可以在多处收藏，但正文只有一份。家具具有明确用途，工作台负责新建与模板，资料箱负责导入和分拣，鱼塘负责捕捉与回顾，书桌负责编辑。沉浸与专注模式共用编辑会话，环境变化不应中断思考。灵感的“抛入、浮现、整理、放生”对应真实笔记流程，不使用与写作无关的升级系统。

这些是产品设计选择，不宣称相较所有 Minecraft 风格应用均为独家功能。美术使用原创模型与纹理；不把 Minecraft 或其他游戏的名称、素材或品牌作为本应用资产。

## 2 用户与使用场景

### 2.1 目标用户

| 用户 | 主要任务 | 最看重的体验 |
| --- | --- | --- |
| 已使用 Obsidian 的个人用户 | 在已有库中写作、回顾和分类 | 文件互通、语法保留、并发不丢内容 |
| 学生与研究型用户 | 整理阅读笔记、PDF、文献卡片 | 按主题组织、快速回找、模板 |
| 作者与创意工作者 | 捕捉想法、持续写长文 | 低干扰环境、可靠输入、专注模式 |
| 偏好空间整理的个人用户 | 用书房布置表达项目与兴趣 | 位置可记、分类直观、布置不影响正文 |

当前不服务团队知识库管理员、多人协作编辑、复杂出版排版和大型企业文档管理。

### 2.2 关键用户故事

- US01：我选择现有 Obsidian 库，就能打开原笔记，不产生同步副本。
- US02：我记住某个项目在二楼左侧书架，也能直接搜索同一本笔记。
- US03：我坐到书桌输入中文、插表格、改格式，内容自动保存，WASD 不会带动人物。
- US04：我切到专注模式后继续同一句话，撤销记录和阅读位置还在。
- US05：我把一个 PDF 放进资料箱，原文件不变，之后可以找到并用系统应用打开。
- US06：我随手记下一句话，之后从鱼塘把它整理成正式笔记，或移到回收目录。
- US07：我在另一个应用改同一文件，书房能刷新或让我处理冲突，不悄悄覆盖。
- US08：我不启用 AI、不联网，也能完成新建、编辑、搜索和整理。

## 3 范围与版本口径

### 3.1 优先级与状态定义

需求优先级与测试问题优先级分开记录。R0 为首个稳定版必须完成，R1 为核心体验增强，R2 为可延期的环境或智能扩展。未完成的 R1/R2 若保留在发布包中，同样不能存在数据损坏、越权写入或阻断核心操作的问题；必要时明确标为实验功能或关闭入口。

“实现存在”指代码和入口已经存在；“自动化通过”指指定测试通过；“原生部分通过”指已在 macOS 应用实际完成特定流程；“原生待验收”不能视为已完成。测试结果以包含补丁的独立测试副本为准，不自动适用于未合并补丁的桌面目录。

### 3.2 功能范围

| 模块 | 优先级 | 当前证据 | 发布要求 |
| --- | --- | --- | --- |
| 库选择与隔离 | R0 | 选择库原生通过；切库有回归测试 | 无跨库误写，错误时保留当前库 |
| Markdown 与 TXT | R0 | 自动化及主要原生流程通过 | 完成输入法、恢复和格式组合验收 |
| 保存与外部冲突 | R0 | 原生磁盘刷新、冲突、失败关闭保护通过 | 补齐真实 Obsidian 与异常退出 |
| 搜索与两种书架 | R0 | 自动化、旧浏览器及中文搜索原生检查 | 验证千篇 UI 性能和目录变更 |
| 导入与外部打开 | R0 | 底层与模拟 UI 有测试 | 完成 Word/PDF、Finder 全链路 |
| 第一人称书房与专注 | R0 | 主要切换可用 | 补齐输入优先级、碰撞、减弱动态 |
| 家具与布局恢复 | R0 | 规则和序列化测试 | 逐件布置及真实重启恢复 |

| 灵感池与模板 | R1 | 纯函数和部分旧浏览器检查 | 原生捕捉、归档、撤销 |

| 主题与窗景及花园 | R2 | 实现存在，部分规则测试 | 场景可用性、素材处理及降级 |

### 3.3 从原方案到当前产品的变化

| 原方案 | 当前实现或问题 | 本 PRD 的处理 |
| --- | --- | --- |
| Word 只归档和外部打开 | 已加入 DOCX 基础编辑器 | 列为 R1，复杂文件默认保护，外部打开仍保留 |
| 不在应用内移动真实文件 | 灵感归档、资料箱、管家已有移动操作 | 限定明确入口；增加影响提示与撤销，不承诺自动修复正文链接 |
| 同名导入询问保留两份或取消 | 拖放路径自动保留两份；旧清单同时保留两种说法 | 区分文件对话框与拖放入口，均不静默覆盖；交付前统一文案 |
| 不修改 Obsidian 配置 | 模板支持读取 templates.json | 允许只读获取模板目录，不写入配置，不执行插件 |
| 默认关闭镜头摇晃 | 当前引擎有轻微摇晃，读取系统减少动态偏好 | 首个稳定版增加明确设置并默认关闭，属于待落实差异 |
| 第一版仅固定书房 | 已有院子、多楼层和主题 | 空间仍有边界；扩展内容不得拖慢核心验收 |

### 3.4 明确不做

首个稳定版不增加账号、云同步服务、多人协作、开放世界、逐方块建造、交易系统、战斗、生存机制、排行榜、Obsidian 插件运行环境、完整 Canvas/Dataview/块引用渲染、专业 Word 排版、PDF 内置编辑或全格式 OCR 搜索。不承诺所有外部应用对扩展 Markdown 的视觉效果完全一致。

## 4 信息架构与核心流程

### 4.1 入口和页面

| 层级 | 入口 | 内容与退出方式 |
| --- | --- | --- |
| 启动 | 欢迎页、最近使用库 | 选择库；取消后停留，不创建目录 |
| 空间 | 第一人称书房、楼层与院子 | 家具交互、探索；Esc 释放鼠标并进入菜单 |
| 写作 | 书桌与专注编辑 | 正文、保存状态、源码/实时预览、预览面板 |
| 快速操作 | 搜索、最近打开、新建、随手记 | 不要求走到家具；支持键盘关闭 |
| 整理 | 书架、工作台、资料箱、鱼塘 | 分类、模板、导入、归档、回收 |
| 扩展 | 管家、AI、声音、窗景、宠物 | 清晰的独立面板；失败不关闭当前笔记 |
| 设置 | 暂停菜单与设置入口 | 库切换、布局、视觉、声音、网络扩展 |

### 4.2 核心任务流程

**首次进入：** 启动 → 选择本地目录 → 验证访问权限和库边界 → 扫描文件 → 恢复该库布局或生成默认布局 → 显示书房 → 用户主动点击获取鼠标控制。扫描期间展示状态；失败提供重试和重新选择。

**读写笔记：** 走近书架或搜索 → 选择笔记 → 带到书桌 → 同一会话中编辑 → 停止输入后自动保存 → 需要时切换专注 → 保存成功后离开。打不开的文件显示错误及可用的外部打开入口。

**新建笔记：** 工作台或快捷新建 → 选择 Markdown/TXT/可选 DOCX → 选择模板 → 确认文件名与位置 → 创建 → 进入编辑。取消不产生空文件；同名不覆盖已有文件。

**处理导入：** 选择文件或 Finder 拖入 → 明示目标 → 复制 → 显示成功/失败明细 → 上架或稍后分拣 → 可撤销本次新增副本。导入后动画不代表保存成功，必须以后端结果为准。

**处理冲突：** 发现磁盘变化 → 当前没有未保存内容则刷新；否则暂停自动覆盖 → 展示本地和磁盘版本 → 用户选择磁盘、本地或手动合并 → 再次校验磁盘版本 → 成功保存或继续比较。

## 5 本地库与文件需求

### 5.1 库选择与切换

**VAULT01｜R0。** 一次只打开一个库。库可以是现有 Obsidian Vault 或普通目录；不复制整个库，不要求初始化私有数据库。选择器取消、路径失效或权限不足时，不改变当前库。

**VAULT02｜R0。** 切换前先保存当前笔记、Word 会话、布局及待写附加数据。存在冲突、保存错误或无法确认落盘的内容时阻止切换。切换成功后清空旧库会话和路径缓存，再载入新库；同名相对路径不能复用旧正文。

**VAULT03｜R0。** 所有正文读写限制在选择的库内。规范化相对路径，拒绝越界路径；不自动跟随指向库外的符号链接。外部文件只可通过明确授权的导入、图片或音频选择入口读取。

### 5.2 文件类型与操作边界

| 类型 | 本应用读取和编辑 | 索引范围 | 降级方式 |
| --- | --- | --- | --- |
| .md | 源码、实时预览、独立预览 | 文件名与文本正文 | 保留未知语法原文 |
| .txt | 纯文本编辑，不启用 Markdown 格式菜单 | 文件名与文本正文 | 原样保存换行 |
| .docx | 基础编辑，受复杂格式保护 | 文件名；正文索引能力需另行确认 | 系统 Word 或其他默认应用 |
| .doc | 归档，不承诺内置编辑 | 文件名 | 系统应用 |
| PDF 与其他附件 | 导入、引用、定位、外部打开 | 文件名 | 明示系统应用不可用的错误 |
| 本地图片 | 笔记预览、画框或窗景 | 文件名 | 解码失败时显示占位和路径 |

**FILE01｜R0。** 默认新建写入 Notes；从目录书架新建写入当前目录，绑定根目录时直接写库根目录。界面必须在创建前展示去处。不存在的必要子目录由明确的新建/导入操作创建。

**FILE02｜R0。** 不把“支持归档”写成“支持所有格式编辑”。搜索 PDF、图片和未解析附件时只承诺文件名搜索，不承诺 OCR、语义搜索或附件全文索引。

**FILE03｜R0。** 外部删除显示失效引用，保留当前会话；不自动重建。能可靠识别的重命名更新引用；不能识别时显示失效并提供重新关联需求。重新关联入口的实现与原生可用性须确认。

### 5.3 导入与分拣

**IMPORT01｜R0。** 导入只复制，不移动源文件。正常完成后校验源文件内容和修改时间不变；文件夹导入保留子目录。文件对话框遇到冲突提供保留两份或取消；拖放路径可自动保留两份，但必须在回执列出改名结果。

| 落点 | 去处 | 附加行为 |
| --- | --- | --- |
| 目录书架 | 对应库内目录 | 更新目录展示 |
| 收藏书架 | Imports | 增加该书架引用 |
| 书桌 | Imports | 导入后打开支持的文件 |
| 鱼塘 | Inbox | 显示可整理的资料或灵感 |
| AI 工作台 | 默认导入目录 | 选择支持的文字作为附件，发送前仍需确认范围 |
| 资料箱、地面、专注模式 | Imports | 等待分拣 |
| 窗户上的图片 | 窗景处理流程 | 不把原图当作要修改的笔记 |
| 留声机上的音频 | 应用数据目录 | 增加歌单，不污染笔记目录 |

**IMPORT02｜R0。** 拖入前显示家具描边与去处；Retina 坐标转换必须准确。库内已有文件拖到收藏书架仅加引用，不重复复制；不能把库内已有文件当成导入副本撤销。

**IMPORT03｜R0。** 批量导入部分失败时列出成功项、失败项及原因，允许重试失败项。撤销只处理本次新增副本和新增引用；副本移入 .trash，不误删原文件。

**SORT01｜R1。** 资料箱支持待分拣与全部资料、多选上架。收藏书架只改引用；目录书架会移动真实文件，执行前展示文件数量、来源、目标及链接风险。撤销遇到同名文件不得覆盖。

## 6 编辑器需求

### 6.1 编辑会话与显示模式

**EDIT01｜R0。** 沉浸书页和专注界面使用同一编辑会话。切换不重新加载正文，不清空撤销历史，不丢选区和滚动位置；返回后焦点明确。专注模式暂停背景三维渲染，关闭后恢复。

**EDIT02｜R0。** Markdown 提供源码与实时预览切换，以及独立预览面板。实时预览只改变展示：光标所在行显示原文，其他行显示排版。切换显示不能自动规范化 YAML、未知语法、空白或换行。

**EDIT03｜R0。** 中文正文采用清晰字体，不能用像素字体替代输入区域。中文输入法组合期间，Enter、Esc、方向键和空格优先交给输入法；编辑框和弹窗有焦点时关闭人物移动和家具快捷键。

### 6.2 Markdown 支持

正文支持标题、段落、有序/无序列表、待办、引用、围栏代码、行内代码、分割线、链接、图片和基础表格；扩展支持高亮、下划线、小字、有限文字颜色与基础提示框。保留 YAML 属性和不支持的语法。公式命令只承诺插入公式分隔符；完整数学排版渲染不在当前已验收范围。

### 6.3 斜杠菜单

**EDIT04｜R0。** 在 Markdown 行首、空白后或中文后输入 / 可触发；顿号“、”仅在行首或空白后作为备选触发。普通“苹果、香蕉”、英文路径、日期、网址中的斜杠不触发。围栏代码、缩进代码、行内代码和 YAML 中不触发。输入法尚未提交时不抢焦点。

菜单支持中文、英文和拼音首字母筛选，例如 bg 对应表格；方向键选择、Enter 执行、Esc 关闭。Esc 首先关闭菜单，不能同一次操作把用户带离书桌。连续两个字符没有匹配时收起菜单，但保留已输入文本。执行后移除触发串，把光标放到可继续输入的位置；撤销行为应自然且可测试。

| 命令组 | 内容 |
| --- | --- |
| 段落 | 正文、三级标题、列表、编号列表、待办、引用 |
| 结构 | 表格、提示框、代码块、分割线 |
| 连接 | Wikilink、网址、图片 |
| 其他 | 公式片段、今天日期、高亮、下划线、小字 |

### 6.4 选择工具条

**EDIT05｜R0。** 选中文字显示工具条，支持标题级别/正文/小字、粗体、斜体、下划线、删除线、高亮、行内代码、双链和默认加七种颜色。工具条不能遮挡选区与输入法候选窗；点击按钮后保留可继续编辑的选区。再次应用可切换或移除对应格式。

“字号”使用 Markdown 标题级别与 small 标记表达，不提供任意像素字号承诺。下划线写入 u 标签，高亮写入双等号，颜色写入有限的 span 样式；渲染时净化 HTML。代码与 YAML 中的同样字符必须保持字面展示。

### 6.5 表格

**EDIT06｜R0。** 插入时选择列数和数据行，界面明确尺寸是否包含表头。生成合法 Markdown 表头、分隔行与数据行。提供加行、加列、删行、删列、左/中/右对齐及整理；删除最后一行/列时不得生成无效表格或丢失整篇其他内容。

Tab 跳到下一格并选中内容，Shift+Tab 回到上一格；最后一格 Tab 增加一行。自动整理不改变单元格内容，正确处理转义竖线。光标离开表格后显示表格，点击单元格恢复原文并进入目标格。多行操作在 LF 与 CRLF 文件中都必须保持正确行数与光标位置。

复杂合并单元格、嵌套表格和电子表格公式不在范围。新增表格尺寸应有上限，避免瞬时生成过大文档；当前命令实现有 12 列、40 数据行上限，UI 与命令边界需一致。

### 6.6 TXT 与 Word

**EDIT07｜R0。** TXT 使用同样的保存、恢复和冲突状态，但不渲染 Markdown，不弹格式工具条或斜杠菜单。

**WORD01｜R1。** DOCX 支持基础段落、标题、粗斜体、列表和表格，提供页面式编辑。首次写回前保留原文件备份；检测到不支持或可能丢失的复杂格式时默认只读，解释风险并保留系统应用打开入口。不得仅通过“文件能导出”认定 Word 兼容通过。

**WORD02｜R1。** Word 与 Markdown 切换时只显示当前编辑器，但保留各自会话。外部读取转换期间若用户继续输入，读取结果不得覆盖新输入。外部替换为复杂文档后重新评估只读状态；原文件删除后仍可恢复草稿，显式确认后才重建。

Word 的 Notion 式菜单和选择工具条列为后续候选需求，当前不承诺实现。没有必要把 Markdown 的语法命令直接套到 DOCX。

## 7 保存与恢复需求

### 7.1 状态与动作

| 状态 | 界面 | 系统行为 | 用户动作 |
| --- | --- | --- | --- |
| 已保存 | 明示已保存，可显示时间 | 等待输入或外部变更 | 继续编辑 |
| 未保存 | 明示未保存 | 停止输入约 1 秒后保存 | Cmd+S 立即保存 |
| 保存中 | 显示进度状态 | 完成原子写入和版本校验 | 可继续输入，后续内容进入下一次保存 |
| 保存失败 | 原因与重试提示 | 保留正文与草稿，不谎报成功 | 重试、修复权限或磁盘问题 |
| 冲突 | 本地/磁盘比较 | 暂停自动覆盖，保留双方 | 选磁盘、本地或合并结果 |
| 文件失效 | 删除或移走提示 | 不自动创建文件 | 关闭、重新关联或明确重建 |
| 恢复草稿 | 时间及来源说明 | 先比较草稿与当前磁盘 | 恢复、比较或明确丢弃 |

### 7.2 可靠性要求

**SAVE01｜R0。** 使用同目录临时文件与原子替换。保存前以内容版本/哈希校验磁盘，写入失败保留旧文件。写入期间的新输入不能因为较早请求完成而被标记为已保存。

**SAVE02｜R0。** 恢复草稿保存在应用数据目录，按库和路径隔离。当前会话实现默认约 5 秒保存草稿；冲突与删除场景立即尝试落草稿。异常退出存在尚未落草稿的短暂窗口，不承诺零损失；测试需测量实际恢复边界。

**SAVE03｜R0。** 未保存、保存失败或冲突存在时，关闭窗口与切库不能静默结束。先尝试保存；仍未保存时阻止退出并明确提示。若以后增加“放弃退出”，必须独立确认并说明恢复草稿状态。

**SAVE04｜R0。** 没有本地修改时外部变化自动刷新；有修改时进入比较。冲突处理中磁盘再次变化需再次校验，不能使用陈旧比较结果盲写。已删除的空文件在用户点重建后也必须真正创建。

**SAVE05｜R0。** 对话框关闭、临时离开笔记、切换显示模式不能丢本地冲突正文。恢复会话包括当前内容及必要的撤销/滚动信息；跨库不复用会话。

## 8 Obsidian 互通需求

**OBS01｜R0。** 两款应用读写相同原始文件，不额外建立同步副本；不得写入 .obsidian 配置。可以只读获取模板目录配置，配置不存在或不合法时回退到 Templates。模板路径仍须限制在库内。

**OBS02｜R0。** 支持基础 Wikilink、带显示名称的 Wikilink、Markdown 相对链接、标签和本地图片。相对链接以当前笔记目录解析；多篇同名笔记无法唯一匹配时要求选择，不能静默跳错。未支持的标题定位、块引用、插件查询与 Canvas 数据保持原文，不保证渲染。

**OBS03｜R0。** 基础语法互通与视觉完全一致分开验收。高亮、u/small/span、提示框在真实 Obsidian 中单独验证；主题与插件可能影响显示，产品不得写“显示一定一样”。

**OBS04｜R0。** 实际移动或重命名文件可能破坏相对链接。当前不承诺批量改写笔记正文中的链接。目录归档和管家移动必须说明该边界；需要完整链接维护时优先在用户熟悉的外部工具中处理。应用内引用、最近打开和书架状态应随可识别的移动更新。

## 9 搜索与书架需求

**SEARCH01｜R0。** Cmd+K/Cmd+P 搜索文件名和可索引的文本正文，显示标题、相对路径、匹配片段。Enter 打开，Option+Enter 或“带我去”定位到书架；找不到空间位置时仍能打开文件，不能伪造一个位置。

**SEARCH02｜R0。** 最近打开可直接访问，失效文件标明不可用。索引随新增、修改和删除更新；重建不改变正文。冷启动扫描时允许用户知道进度，不在主输入路径同步构建大量三维书本。

**SHELF01｜R0。** 默认创建收藏书架，存相对路径引用，同一文件可在多个书架出现。去掉引用、移动书架或拆除书架都不删除正文。存在失效引用时显示标识并提供移除引用或重新关联流程。

**SHELF02｜R0。** 目录书架绑定库内目录，可展示直接文件和可进入的子目录；“只放这一层”与递归展示必须有明确区别。支持把当前子目录单独放为书架，绑定改变只影响展示。

**SHELF03｜R0。** 书脊表达类型、颜色与名称，瞄准时显示完整标题和简短摘要。书架面板分页，当前每页 27 项；三维模型按可见范围/分页创建，不为整个库永久生成全部书本。

**SHELF04｜R1。** 灰尘表示久未回顾，发光表示被多篇笔记引用；提示可关闭，不改变文件内容或用户排序。引用统计是可重建的辅助信息，不作为删除文件的依据。

## 10 第一人称空间与布局需求

**WORLD01｜R0。** WASD 移动、鼠标观察、左键/E 交互、空格跳跃；Esc 释放鼠标。第一次进入主动点击后才锁定鼠标。角色不得穿墙、卡在家具或关门时被夹住；无法到达的书架可通过搜索打开。

**WORLD02｜R0。** 进入编辑固定镜头，文字放在清晰界面层，视觉与书页对齐。用户输入时禁用移动、跳跃、家具切换和放置快捷键。按键优先级为输入法 → 编辑器局部菜单 → 当前弹窗 → 写作/探索全局操作。

**WORLD03｜R0。** 预制家具支持新增、选择、移动、旋转、配色和移除；网格吸附及重叠检查实时显示能否放置及原因。实体家具不能挡死必要出口。移动/旋转失败保留原位置；拆除不删除正文。

**WORLD04｜R0。** 布局按库保存，包含版本号、位置、旋转、家具配置、书架引用及视角。保存与载入失败显示错误，不能静默覆盖为默认布局。读取旧版本时迁移并保留可恢复副本；未知字段不应导致整个笔记库不可用。

**WORLD05｜R1。** 保存布局预设，载入前自动留存当前布局。多楼层最多 9 层，各有主题和家具；删除有内容楼层前要求迁移/清空，不能连带删除文件。跨楼层导航明确目标层；一楼提供院子出入口。

**WORLD06｜R0。** 默认关闭镜头摇晃，提供减少动态设置并遵循系统偏好。降低动态时关闭/缩短飞入、弹跳、转场等动画。当前代码存在默认轻微摇晃，本条是发布前待落实需求。

## 11 灵感与模板需求

**IDEA01｜R1。** 书房按 C，应用内其他界面按 Cmd+Shift+I，弹出随手记。这里的快捷键是应用内可用，不承诺操作系统级全局快捷键。输入后存为 Inbox 下普通 Markdown，包含创建时间与灵感标签；空内容不保存，文件名清洗且不覆盖同名文件。

**IDEA02｜R1。** 鱼塘展示待处理灵感，支持继续写作、上架、归档和放生。放生移动到库内 .trash 并提供撤销；不永久删除。若选择目录书架，归档到对应目录；收藏书架的归档目标须明示，不能让用户以为仅添加引用却实际移动文件。

**IDEA03｜R1。** 冒泡被动展示旧灵感或久未回顾的书，用户主动靠近或打开后才查看。回顾不弹系统通知，不要求当天处理。关联天气默认不应制造积压惩罚感，提供关闭和独立天气选择。

**TEMPLATE01｜R1。** 工作台提供空白文档、文献卡片、读书笔记、会议记录和日记。可读取库内模板，预览标题、变量替换结果和保存路径。模板用于创建副本，不修改模板源文件；日期时间变量按本地时间生成，未知变量保留并提示。

## 13 AI 工作台与管家需求

**AI01｜R2。** AI 默认不影响离线流程。用户自行配置服务商、模型和密钥；密钥进入系统钥匙串，不写进笔记、日志或普通布局文件。支持现有 Anthropic、OpenAI 与兼容接口接入路径，但真实服务成功率须实测。

**AI02｜R2。** 发送前清楚展示附带笔记/附件的范围，默认不上传整个库。外部服务接收用户选择的内容，界面需在首次启用时说明。AI 回答可以复制、插入当前笔记或另存；插入可撤销，写入失败按普通保存错误处理。

**AI03｜R2。** 流式输出可取消；连接失败、密钥失效、限流和服务错误显示可理解的提示。未完成输出不能冒充完整回答，不应重复写入正文。AI 请求与环境天气的失败不影响当前文件编辑。

**BUTLER01｜R2。** 管家具有离线固定命令和可选模型工具调用两种模式。查找笔记、说明位置、带路属于低风险操作；新建、移动、回收、批量整理和布局替换先展示操作计划，由用户确认后执行。

**BUTLER02｜R2。** 笔记正文和模型输出均不能直接授予文件操作权限。每项写操作仍经过应用参数校验、库边界检查和确认规则；失败可追溯，撤销不覆盖后来产生的文件。用户拒绝后不得换一种调用继续执行。

### 14.2 默认目录

| 位置 | 用途 | 删除应用后的要求 |
| --- | --- | --- |
| 库内 Notes | 默认新建笔记 | 正常可读 |
| 库内 Inbox | 随手记与灵感 | 正常可读 |

### 14.3 技术模块约束

采用 Tauri 2、React、TypeScript、Three.js 和 CodeMirror 6。文件层负责路径校验、扫描、原子写入、监听、索引与系统打开；笔记层负责编辑会话、语法显示、保存状态和冲突；空间层只接收文件元数据与操作结果，不直接写笔记文件。DOCX 转换与编辑独立于 Markdown 会话，共享文件层的安全语义。

| NFR06 | 稳定性 | 60 分钟混合编辑和模式切换不崩溃、不持续增长会话/模型资源；内存上限由基准测试确定 |
| NFR07 | 大文件 | 至少检查 1MB/5MB/20MB 文本与大附件；卡顿时提供源码/外部打开，不静默截断 |
| NFR08 | 可用性 | 最小窗口 860×560 和 Retina 缩放下菜单、表格、冲突按钮可操作；主要操作可键盘完成 |
| NFR09 | 可访问性 | 中文字体清晰、焦点可见、状态不只靠颜色；读屏可识别输入、按钮和保存状态 |
| NFR10 | 网络与隐私 | 未启用 AI/真实天气时核心功能不依赖网络；日志不记录正文、密钥或未经选择的附件内容 |
| NFR11 | 安装 | 当前重点验证 Apple Silicon；配置的 macOS 11 最低版本不等同于已实测覆盖，Intel/最低系统另列矩阵 |

空间参考分辨率与现有窗口配置一致；性能测试以发布构建为主，调试构建结果单独记录。默认无云端行为分析；如增加可选诊断，必须显式授权且不能采集笔记正文。

## 16 验收矩阵与测试证据

### 16.1 已有证据

2026年10月7日的独立测试副本通过 20 个前端测试文件、138 项测试及 TypeScript/Vite/macOS 构建。本轮新增 21 项编辑器回归，覆盖 CRLF 命令位置、跨行替换、代码/YAML 语境。

上一轮另有 51 项 Rust 测试及 22 项使用模拟后端的浏览器检查；本轮没有重跑这两组，不可合并宣传为本轮完整端到端测试。上一轮千篇库扫描约 11ms、冷搜索约 50ms、暖搜索约 2.6ms 是特定底层测试数据，不代表完整 UI 性能指标已达成。

原生已经检查库选择、中文文件搜索、粗体、模式切换后撤销、表格常用操作、待办、基础双链、本地图片、CRLF 保存、真实磁盘外部刷新、脚本并发冲突、保存失败和关闭保护。成功打开测试应用不等于所有原生功能通过。

### 16.3 缺陷与发布门槛

存在数据丢失、静默覆盖、跨库写入、组合输入阻断、关闭丢稿等严重问题时停止稳定版发布。所有 R0 用例完成且无未解决严重缺陷，构建和测试可复现，才可给出“核心稳定版验收完成”的结论。未验收扩展入口必须明确标识或暂不随稳定版开放。

两份补丁 fixes.patch 与 notion-fixes.patch 已交付桌面目录，但本次读取仍未看到新增编辑器修复出现在桌面相应源码中。发布负责人应确认实际合并状态并重建，不能直接把测试副本的通过结果记到另一份二进制上。

## 18 产品验证与风险

### 18.1 建议试用指标

首轮安排 5 至 8 位符合目标画像的试用者，以测试库完成选库、找到笔记、插表格、导入附件和处理冲突。任务成功率目标至少 90%，关键数据操作错误为零。记录完成时间、求助次数、是否使用空间入口以及为何切到专注模式，不以使用时长或打卡作为成功指标。

连续一周个人试用重点记录“想法能否被重新找到”“装饰是否分散注意”“是否因为不信任保存而反复打开 Finder 检查”。收集可自愿导出的匿名任务结果，不默认上传内容或文件路径。

### 18.2 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 环境功能持续扩张 | 核心笔记可靠性验证被推迟 | 以 R0 门槛阻止扩散，扩展可独立关闭 |
| Markdown 自定义展示误解析 | 编辑中隐藏/错选文字 | 语法树限定上下文，LF/CRLF 与中文组合回归 |
| Word 格式往返损失 | 文档布局或结构变化 | 复杂格式只读、首次备份、外部应用降级 |
| 应用内移动断链 | 关联资料无法打开 | 不承诺自动修链，执行前提示，支持撤销 |
| 外部应用竞争写入 | 两边内容相互覆盖 | 哈希校验、冲突比较、草稿及真实双应用测试 |
| 三维场景耗电或眩晕 | 无法长时间写作 | 专注暂停渲染、减少动态、画质降级 |
| AI 误操作或内容泄露 | 文件被移动或发往错误服务 | 明示发送范围、写操作确认、钥匙串与库边界 |
| 索引和附加状态损坏 | 书架/最近打开异常 | 原文独立、索引可重建、布局版本和备份 |

### 18.3 需要产品负责人确认的决定

- D01：Word 基础编辑是否随首个稳定版发布，还是暂时保留为实验入口。
- D02：同名文件对话框与拖放采用两种交互，还是统一为自动保留两份并显示回执。
- D03：当前目录移动能力是否继续开放；若开放，接受不自动改写正文链接的边界。
- D04：是否采纳默认关闭镜头摇晃、R2 扩展独立可关闭的建议。
- D05：首发仅支持已验收的 Apple Silicon 环境，还是投入 Intel 与更低系统版本测试。
- D06：是否在后续版本增加 Word 命令菜单、布局导出和更多 Obsidian 语法兼容。

这些决定不阻止合入已验证的数据保护修复，也不改变既有本地文件的所有权和存储位置。
